## Text encoding fixes

- Export `SQLConnectW` so Windows recognizes the driver as Unicode and
  preserves wide connection parameters instead of converting them to ANSI.
- Report implemented ODBC functions and expose connection attribute getters
  for the Driver Manager's connection initialization.

- Return UTF-16 string metadata from `SQLGetInfoW`, including driver versions
  and database names, while preserving native ODBC numeric types.

- Recognize braced ODBC values such as `ClientCharset={GBK}`.
- Preserve parameters after double quoted values such as
  `Project="example";ClientCharset=GBK`.
- Preserve the client charset in the completed connection string returned by
  the driver, including escaped attribute values.
- Report 1.0.1 consistently in the MSI, DLL and ODBC driver metadata.

## Diagnostics

New `[ODBC-Encoding]` INFO messages show the loaded driver version, the
effective client charset and whether the application requests `SQL_C_CHAR`,
`SQL_C_WCHAR` or binary data. These messages omit credentials, SQL text and cell
values, and are limited to each connection and result column/type.

See [Power BI encoding troubleshooting](https://github.com/aliyun/alibabacloud-maxcompute-odbc-driver/blob/v1.0.1/docs/encoding-troubleshooting.md).
`ClientCharset` controls narrow character results; Unicode results always use
UTF-16. These fixes address the reproduced driver defects; an individual Power
BI connection can require further diagnosis.

The GitHub Windows packages are unsigned. Their SHA-256 digests are included in
`SHA256SUMS`. The existing separately hosted OSS download is not updated by this
release.
